Lean Startup

Build, measure, learn. As fast as you can.

Build

The minimum you need to test a hypothesis.

Measure

What real customers do, not what they say.

Learn

Persevere or change direction, then go around again.

“The minimum viable product is that version of a new product which allows a team to collect the maximum amount of validated learning about customers with the least effort.”

Eric Ries, The Lean Startup (2011)

In the game. Launching from 50% of the MVP instead of at 100% raises learning velocity.

Session 2 · From problem to MVP

05

Eric Ries’s build-measure-learn loop: a startup’s unit of progress is not code written but validated learning, meaning what customer data confirms or disproves. What matters is how fast you go around the loop, not how perfect each lap is. So an MVP is not “a small product” but an experiment: it has to be enough to learn from, not enough to please. Ries also warns against “vanity metrics,” the numbers that always go up (total users, visits) and don’t tell you whether the hypothesis holds. Question for the class: which number would tell you that you are wrong?
